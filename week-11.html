Week 11 · Thursday, November 12 · Phase 2 — Design & Presentation

Essential Design System, Part 2

Spacing scale and core components: buttons, inputs, cards, navigation.

Spacing is the invisible half of the system. Then the components that carry it — built once, correctly, so both pages at both breakpoints assemble fast.

Due this week

Design system v1

  • Color palette: primary, secondary, neutral, semantic
  • Typography: typefaces, scale, line-height
  • Spacing scale
  • Buttons, inputs, cards, navigation with variants
  • Usage documentation

Session plan ≈170 min

25 minSpacing scale
A base unit and a scale. How spacing encodes density, and how density expresses your art direction.
55 minCore components
Buttons, inputs, cards, navigation. Variants for every state you'll actually use.
40 minResponsive behavior
Each component tested at mobile and desktop widths before it's declared done.
30 minDocumentation
Usage notes per component: when to use it, when not to, and what it inherits.
20 minSystem review
Swap files. Find the hardcoded values.

In-class activity: System v1

  1. Define the spacing scale as number variables and apply it through Auto Layout — no eyeballed padding.
  2. Build buttons, inputs, cards and navigation with real variants and states.
  3. Stress-test each at 375px and 1440px.
  4. Write one usage note per component. Audit for hardcoded values and bind them.

Working with AI this week

Use it as a checklist and a critic, not a builder.

Prompts to start from

  • “What component states am I likely to need on a PDP that I haven't built — loading, error, out-of-stock, disabled?”
  • “Review these usage notes for ambiguity.”

What to verify

  • Every suggested state has to appear somewhere in your two pages or it doesn't get built.

Evidence to log

These feed the cognitive-process rubric. Capture them as you work.
